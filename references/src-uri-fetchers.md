# SRC_URI Fetcher Syntax

## git

```
SRC_URI = "git://github.com/org/repo.git;protocol=https;branch=main"
SRCREV = "<explicit commit hash>"
S = "${WORKDIR}/git"
```

- `protocol=https` (or `ssh`) is almost always required; otherwise bitbake's git
  fetcher defaults to the native `git://` protocol, which most modern hosting
  services don't support.
- `branch=` must be consistent with `SRCREV` (the `SRCREV` must be a commit in
  that branch's history).
- For submodules use `gitsm://` in place of `git://`; the rest of the syntax is
  the same.
- `SRCREV = "${AUTOREV}"` fetches the latest commit of the branch every time —
  **only suitable for dev iteration**; a production/reproducible recipe always
  pins an explicit hash.

## wget / https tarball

```
SRC_URI = "https://example.com/foo-${PV}.tar.gz"
SRC_URI[sha256sum] = "<64-hex, from sha256sum>"
S = "${WORKDIR}/foo-${PV}"
```

- `S` must match the actual top-level dir name after unpacking, which is not
  necessarily the same as the tarball filename — check after unpacking.

## file:// local files (including patches)

```
SRC_URI = "file://foo-1.0.tar.gz \
           file://0001-fix-cross-compile.patch"
```

- Only files under a `files/` subdir next to the recipe (or a folder named after
  the recipe) can be referenced with `file://`. A locally-packed vendor tarball
  (see below) goes through this path.
- Patch files are listed in SRC_URI in apply order; bitbake applies them in
  sequence.

## Two modes for a local-path input

### (1) externalsrc — dev mode, fast iteration, not reproducible

```
inherit externalsrc
EXTERNALSRC = "/home/user/dev/foo"
EXTERNALSRC_BUILD = "/home/user/dev/foo/build"   # specify for out-of-tree builds; optional
```

- Skips fetch/unpack entirely and builds in place against this path, so an edit
  to the source is immediately visible with `bitbake -c compile foo` — great for
  edit-and-test.
- **Cost:** the recipe has no version pinning; results aren't guaranteed to match
  on another machine or at another time. Switch to the vendor-tarball or
  git+SRCREV mode below before productionizing.

### (2) vendor tarball — reproducible mode

Pack the local dir and place it in the layer:

```sh
tar -czf files/foo-1.0.tar.gz -C /path/to/local/dir .
```

```
SRC_URI = "file://foo-1.0.tar.gz"
S = "${WORKDIR}/foo-1.0"
```

Good for "this code has no upstream repo, but I need a recipe others / CI can
reproduce."

## npm / crate (special fetchers, need the matching class)

- `npm://` with the node class provided by `meta-nodejs`.
- `crate://` with the crate list generated by `cargo`/`cargo-bitbake` (see the
  cargo section of `bbclasses.md`).
- Both need extra layer/tool support; they're not usable out of the box with
  oe-core alone.
